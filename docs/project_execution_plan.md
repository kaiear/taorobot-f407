# 自动巡检机械臂小车总体实施方案

本文档用于回答当前项目“下一步怎么做、弱下位机最终保留什么、上位机如何开始、什么时候装车和装摄像头、两个零基础组员怎么分工”的问题。

当前判断：项目路线应采用“弱下位机 + 强上位机”。STM32 只负责安全可靠地执行底盘、电机、舵机、传感器基础读写和急停；树莓派负责 ROS、摄像头、巡检逻辑、导航、识别、机械臂动作编排。

---

## 1. 当前状态结论

### 1.1 已经具备的基础

- STM32 下位机工程已经整理到 `firmware/SJRobot_center/project/SJRobot_center.uvprojx`。
- 小车轮子已经可以转动，说明电机驱动、PWM 输出、电源链路至少部分有效。
- 当前底盘运动学默认是麦克纳姆轮：`ROBOT_TYPE = ROBOT_MEC`。
- USART2 已经存在 ROS/树莓派通信入口，帧头为 `0xAA 0x55`，波特率 `115200`。
- 舵机底层已有 6 路 PWM 控制接口 `duoji_doing_set(index, aim, time)`。
- 遥控器/USB 手柄输入链路已经存在：`app_ps2.c -> Vel.TG_IX/IY/IW -> ROBOT_Kinematics()`。

### 1.2 当前最重要的风险

- 轮子能转不等于底盘能正确运动，必须完成 A/B/C/D 轮子位置、方向、编码器闭环验证。
- 舵机不能直接装机械臂满行程测试，必须先单路低幅度验证中位和安全范围。
- 不应过早安装摄像头和上位机复杂算法，否则底层不稳会导致问题无法定位。
- 当前代码里原厂机械臂和 ROS 协议可复用，但需要先验证协议和安全限幅，不能直接相信全部逻辑。

## 2. 推荐总体路线

### 阶段 0：安全基线

目标：保证默认上电不会自动乱跑。

必须做到：

1. 默认上电电机速度为 0。
2. 默认上电不让舵机大幅动作。
3. 所有测试代码用宏开关控制，测试完默认关闭。
4. 任何串口异常包不应触发危险动作。
5. 遥控器松手、串口 stop、断电都能让小车安全停止。

验收标准：车轮悬空上电 1 分钟，电机不自动转；舵机不大幅运动；LED 或串口心跳正常。

### 阶段 1：底盘正常使用

目标：让麦克纳姆底盘可以稳定完成前进、后退、横移、旋转、停止。

执行顺序：

1. 悬空单独测试 `MOTOR_A/B/C/D_SetSpeed(300)` 和 `-300`。
2. 记录 A/B/C/D 对应实际轮子位置。
3. 记录正数和负数对应实际转向。
4. 检查 `kinematics.c` 中 A/C 反向是否符合实车。
5. 使用低速速度指令测试 `Vel.TG_IX` 前后、`Vel.TG_IY` 横移、`Vel.TG_IW` 旋转。
6. 落地低速测试，速度从 300、500、800 逐步增加。
7. 更新 `docs/motor_mapping.md`。

验收标准：

| 动作 | 通过标准 |
|---|---|
| 前进/后退 | 不明显跑偏，方向正确 |
| 左/右平移 | 能横移，轮子方向符合麦轮逻辑 |
| 左/右旋转 | 能原地旋转 |
| 停止 | 松开遥控或发 stop 后立即停 |
| 安全限速 | 不会突然满速 |

### 阶段 2：遥控器调试

目标：上位机没写好之前，也能用遥控器独立调试底盘。

源码链路：

```text
USB 手柄
  -> app_ps2.c
  -> Vel.TG_IX / Vel.TG_IY / Vel.TG_IW
  -> ROBOT_Kinematics()
  -> MOTOR_A/B/C/D_SetSpeed()
```

执行顺序：

1. 确认 USB 手柄插入后 `ps2_do_ok` 有数据刷新。
2. 测左摇杆上下是否改变 `Vel.TG_IX`。
3. 测左摇杆左右是否改变 `Vel.TG_IY`。
4. 测右摇杆左右是否改变 `Vel.TG_IW`。
5. 测摇杆松开是否归零。
6. 记录手柄型号、摇杆方向、是否需要反向。

验收标准：不用树莓派，只靠遥控器能完成底盘六个基础动作和停止。

### 阶段 3：USART2 与树莓派通信

目标：树莓派或电脑能通过串口安全控制底盘和舵机。

源码链路：

```text
树莓派/电脑
  -> USART2 PD5/PD6 115200
  -> Drive_program/uart2.c
  -> ID_ROS2STM_VEL / ID_ROS2STM_ARM / ID_ROS2STM_HAND
  -> Vel 或 ros_servo
```

先测低风险指令，再测高风险动作：

1. 串口心跳或蜂鸣器指令。
2. stop 指令。
3. 低速底盘速度指令。
4. 单路舵机中位指令。
5. 多路舵机预设姿态。

验收标准：

- 树莓派能打开串口 `/dev/ttyUSB0` 或 `/dev/ttyAMA0`。
- 发送 `0xAA 0x55` 协议帧后 STM32 能解析。
- stop 指令有效。
- 速度指令只在低速范围内生效。
- 舵机指令只在安全 PWM 范围内生效。

### 阶段 4：舵机验证

目标：确认 6 路舵机 index、方向、中位、安全范围，再考虑机械臂装配。

执行顺序：

1. 不装机械臂或卸载连杆，只接单个舵机测试。
2. 每路先发 1500us，看是否为合理中位。
3. 小幅测试 1300us 和 1700us。
4. 记录每路实际关节、方向、安全最小/最大 PWM。
5. 特别记录 `index == 3` 源码反向逻辑。
6. 确认夹爪 open/close PWM 范围。
7. 更新 `docs/servo_mapping.md`。

验收标准：6 路舵机都能单独控制，且每一路都有“中位、安全最小、安全最大、实际关节、方向”记录。

### 阶段 5：装车、装机械臂、装摄像头

只有满足以下条件后才建议正式装车：

- 底盘六个动作已经通过。
- 遥控器可用，松手停止可靠。
- USART2 stop 和低速速度控制可靠。
- 舵机安全范围已经记录。
- 默认上电不会自动跑电机或大幅转舵机。
- 电池、电机供电、树莓派供电不会互相拉垮。

装车顺序建议：

1. 先装底盘和电池，测试遥控底盘。
2. 再装树莓派和网线/SSH，测试串口控制底盘。
3. 再装摄像头，测试视频流，不启用自动运动。
4. 再装机械臂，先断开末端负载，只跑预设安全姿态。
5. 最后做巡检流程：移动到点位、停车、拍照/识别、机械臂动作、回传结果。

## 3. 弱下位机最终应该是什么样

最终 STM32 不应该承担复杂巡检逻辑，也不应该做视觉、路径规划、任务调度。它应当像“实时执行器控制板”。

### 3.1 STM32 保留功能

| 模块 | STM32 保留内容 |
|---|---|
| 电机 | PWM 输出、编码器读取、PID 速度闭环 |
| 底盘 | 麦轮逆运动学、速度限幅、停止 |
| 舵机 | 6 路 PWM 输出、安全限幅、平滑动作 |
| 通信 | USART2 协议解析、状态回传 |
| 安全 | 超时停车、异常包丢弃、急停 |
| 调试 | 遥控器/手柄作为现场调试入口 |

### 3.2 STM32 不建议保留的功能

| 功能 | 建议放到上位机原因 |
|---|---|
| 巡检流程状态机 | 树莓派更容易改逻辑和记录日志 |
| 摄像头采集 | STM32 不适合处理图像 |
| 目标识别 | 需要 Linux/Python/OpenCV/深度学习 |
| ROS 导航 | 应放在 ROS 上位机 |
| 机械臂高级规划 | 上位机更适合做轨迹、姿态、逆解 |

### 3.3 最终下位机代码结构建议

```text
STM32 下位机
├── main.c                 上电初始化，不放业务逻辑
├── Task_manager.c         固定周期任务调度
├── kinematics.c           麦轮运动学 + PID 输出
├── y_motor.c              电机底层 PWM
├── y_servo.c              舵机底层 PWM
├── uart2.c                上位机协议解析
├── app_ps2.c              遥控器调试入口
└── debug_test.c           可选，统一测试入口，默认关闭
```

核心原则：下位机只接收三类命令：

1. `cmd_vel` 类底盘速度：`vx, vy, wz`。
2. `servo` 类舵机 PWM/角度：`index, pwm, time`。
3. `system` 类安全命令：`stop, reset, beep, heartbeat`。

## 4. 上位机现在怎么开始

你现在可以通过网线直接向树莓派写代码，这是正确的。ROS1 还没安装时，不要一开始就装复杂包，先按“无 ROS 脚本 -> ROS 基础 -> 功能节点”的顺序走。

### 4.1 树莓派准备顺序

1. 确认树莓派系统版本。
2. 配置 SSH，确保 VS Code Remote SSH 或命令行可以登录。
3. 配置固定 IP 或路由器 DHCP 保留地址。
4. 安装基础工具：`git`、`python3-pip`、`python3-venv`、`minicom` 或 `picocom`。
5. 确认串口设备名：`/dev/ttyUSB0`、`/dev/ttyAMA0`、`/dev/ttyS0` 之一。
6. 先用 Python 串口脚本测试 STM32，不依赖 ROS。
7. 再安装 ROS1。

### 4.2 ROS1 选择建议

树莓派常见组合：

| 系统 | 推荐 ROS |
|---|---|
| Ubuntu 20.04 | ROS Noetic |
| Ubuntu 18.04 | ROS Melodic |
| Raspberry Pi OS Debian 10/11 | 不一定适合直接装完整 ROS1，建议容器或换 Ubuntu |

如果你还没装系统，推荐优先使用 Ubuntu 20.04 Server + ROS Noetic。这样资料最多，和 ROS1 兼容最好。

### 4.3 上位机代码第一版不要做复杂 ROS

第一版先写 Python 串口工具：

```text
raspi_upper/
├── serial_client.py       打包/发送 0xAA 0x55 协议帧
├── test_chassis.py        forward/back/left/right/rotate/stop
├── test_servo.py          servo index pwm time
└── README.md              串口测试说明
```

先证明树莓派能控制 STM32，再封装成 ROS 节点。

### 4.4 ROS1 第一版节点

```text
catkin_ws/src/tao_robot/
├── tao_base_bridge/       /cmd_vel -> USART2
├── tao_arm_bridge/        /servo_cmd 或 /joint_cmd -> USART2
├── tao_teleop/            键盘/手柄控制
├── tao_camera/            摄像头采集
└── tao_inspection/        巡检状态机
```

推荐节点顺序：

1. `tao_base_bridge`：订阅 `/cmd_vel`，发送 `ID_ROS2STM_VEL`。
2. `tao_teleop`：键盘发布 `/cmd_vel`。
3. `tao_arm_bridge`：发送单路舵机或机械臂预设姿态。
4. `tao_camera`：打开摄像头，发布图像或保存图片。
5. `tao_inspection`：把底盘移动、拍照、机械臂动作串起来。

## 5. 源码移植复用是否足够

结论：现有源码对“弱下位机”已经基本够用，但还不够“直接装车运行”。

### 5.1 可以直接复用的部分

- `y_motor.c`：四路电机 PWM 底层接口。
- `kinematics.c`：麦克纳姆轮运动学框架。
- `robot.c`：周期调用运动控制的框架。
- `y_servo.c`：6 路 PWM 舵机接口。
- `uart2.c`：USART2 协议帧解析框架。
- `app_ps2.c`：USB 手柄调试入口。

### 5.2 必须补齐/验证的部分

- 电机 A/B/C/D 和实际轮子位置映射。
- 编码器方向和电机方向是否一致。
- 麦轮公式输出方向是否和实车一致。
- 串口协议长度、校验、ID 的上位机打包脚本。
- 舵机每路安全范围。
- 串口超时停车和异常包安全处理。
- 上电默认安全策略。

### 5.3 不建议现在移植到上位机的部分

- 电机 PWM 和编码器 PID 不应移植到树莓派，实时性不如 STM32。
- 基础麦轮逆运动学可以保留在 STM32；上位机只发 `vx, vy, wz` 更稳。
- 舵机 PWM 生成不应移植到树莓派，树莓派只发目标 PWM/角度。

### 5.4 可以移植到上位机的部分

- 底盘高级控制：键盘控制、自动巡检速度规划、路径点逻辑。
- 机械臂高级控制：预设姿态、动作序列、抓取流程、逆运动学。
- 任务状态机：巡检点位、摄像头拍照、识别、回传。
- 日志和调参工具：记录每次速度、舵机目标、识别结果。

## 6. 两名零基础组员分工

核心原则：不要让零基础组员一开始改复杂源码。先让他们“照表测试、记录、提交文档”，再逐步给他们小脚本和封装任务。

### 6.1 组员 A：底盘与遥控器方向

适合交给 A 的任务：弱下位机底盘开发 + 后续上位机底盘控制。

第 1 阶段任务：

1. 会 clone 仓库、打开 Keil、Build、Download。
2. 悬空测试 A/B/C/D 单电机正反转。
3. 填写 `docs/motor_mapping.md` 的轮子位置和方向表。
4. 测麦轮前进、后退、横移、旋转。
5. 测遥控器摇杆控制和松手停止。

第 2 阶段任务：

1. 在树莓派上运行 `test_chassis.py`。
2. 学会发 stop、forward、backward、left、right、rotate。
3. 后续负责 ROS `/cmd_vel -> 串口` 节点。

A 的交付物：

- `docs/motor_mapping.md` 完整记录。
- 底盘六动作测试视频。
- 一个上位机底盘测试脚本。
- 一个 `/cmd_vel` 桥接节点。

给 A 的最小学习清单：

```text
第 1 天：Git clone / pull / commit
第 2 天：Keil Build / Download
第 3 天：C 函数调用和宏开关
第 4 天：Python 串口发送 bytes
第 5 天：ROS topic 和 /cmd_vel
```

### 6.2 组员 B：舵机、串口与机械臂方向

适合交给 B 的任务：弱下位机舵机验证 + 上位机机械臂/协议封装。

第 1 阶段任务：

1. 会 clone 仓库、打开 Keil、Build、Download。
2. 单路测试 `duoji_doing_set(index, 1500, time)`。
3. 对每个 index 测 1300、1500、1700。
4. 填写 `docs/servo_mapping.md`。
5. 用串口助手测试 USART2 收发。
6. 验证蜂鸣器、stop、舵机中位等低风险协议。

第 2 阶段任务：

1. 写 `serial_client.py`，统一封装 `0xAA 0x55` 打包、校验、发送。
2. 写 `test_servo.py index pwm time`。
3. 写夹爪 open/close 脚本。
4. 后续负责机械臂预设姿态和 ROS 机械臂桥接节点。

B 的交付物：

- `docs/servo_mapping.md` 完整记录。
- `docs/serial_protocol.md` 协议测试记录。
- 一个串口协议 Python 封装库。
- 一个单路舵机测试脚本。
- 一个机械臂预设姿态脚本。

给 B 的最小学习清单：

```text
第 1 天：Git clone / pull / commit
第 2 天：PWM 和舵机安全范围
第 3 天：串口助手和十六进制数据
第 4 天：Python struct/bytes/serial
第 5 天：ROS service/topic 控制机械臂
```

## 7. 你本人应该负责的关键决策

不要把以下事项完全交给零基础组员：

1. 是否允许车落地高速测试。
2. 是否修改 `kinematics.c` 的方向符号。
3. 是否修改串口协议格式。
4. 是否装机械臂和摄像头。
5. 是否合并组员分支到 `main`。
6. 是否把 ROS 任务状态机接入真实运动。

你应该每天只验收四件事：

1. 有没有视频证明。
2. 文档表格有没有填完整。
3. 默认上电是否安全。
4. stop 是否有效。

## 9. 最小可实现功能闭环

在不追求完整自动导航的情况下，建议先达成这个闭环：

```text
电脑/树莓派 SSH
  -> Python/ROS 发底盘速度
  -> STM32 控制麦轮移动
  -> 到达点位后 stop
  -> 摄像头拍照/保存
  -> 上位机发机械臂预设动作
  -> STM32 控制舵机动作
  -> 记录巡检结果
```

这个闭环完成后，才继续做自动导航、视觉识别、机械臂高级规划。

## 10. 下一步立即执行清单

你现在的下一步不是装摄像头，而是按以下顺序做：

1. 完成 `docs/motor_mapping.md` 的 A/B/C/D 轮子位置和方向记录。
2. 让底盘悬空完成前进、后退、左移、右移、左转、右转。
3. 让底盘落地低速完成同样六个动作。
4. 跑通遥控器控制，并确认松手停止。
5. 跑通 USART2 stop 和低速速度控制。
6. 单路验证 6 个舵机的 1500、1300、1700。
7. 补齐 `docs/servo_mapping.md` 和 `docs/serial_protocol.md`。
8. 在树莓派上先写 Python 串口脚本，不急着 ROS。
9. Python 脚本能稳定控制底盘和舵机后，再安装 ROS1。
10. ROS `/cmd_vel` 跑通后，再装摄像头和机械臂做系统集成。

最终判断：只要完成以上 1~7，下位机开发就可以认为达到“弱下位机可交付”；完成 8~10 后，项目可以进入真正的自动巡检功能开发。
